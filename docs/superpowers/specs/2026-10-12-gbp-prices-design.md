# Prices in pounds (GBP): design

Agreed with the user on 2026-10-12. Branch: `feature/gbp-prices`.

## Goal

Let a user see Cardmarket prices in pounds. Cardmarket publishes prices only in euros, and Scryfall
passes on only those, so pounds are the euro prices converted at a daily exchange rate.

**Decisions (the user's):**
- **A switch**, like the theme switch: every price and total shows in pounds instead of euros. It
  is remembered in this browser.
- **The rate:** the European Central Bank's daily euro reference rate. The server fetches it with
  the card data and serves it to the app, which converts. The browser contacts no one new.
- **The look:** every converted price is marked approximate (≈£1.80), and each page showing
  values notes the rate and its date once.

**Unchanged:**
- Totals, sorting and every price the server computes stay in euros.
- USD prices on the card page.
- The pricing rules in `testdata/pricing-cases.json`.

## Server

### Source

The ECB's daily reference rates: `https://www.ecb.europa.eu/stats/eurofxref/eurofxref-daily.xml`.
They're free, need no key, and come out around 16:00 CET on each TARGET working day (none on
weekends or holidays). The file is about 2 KB:

```xml
<gesmes:Envelope …>
  <Cube>
    <Cube time="2026-10-10">
      <Cube currency="USD" rate="1.0812"/>
      <Cube currency="GBP" rate="0.8712"/>
      …
```

The GBP `rate` is pounds per euro.

### Package `internal/rates`

**Fetching:**
- HTTPS to `www.ecb.europa.eu` only.
- 10 s timeout, body capped at 64 KB.
- `User-Agent` as for Scryfall.

**Parsing:** `encoding/xml`. It takes the dated `Cube` and its GBP rate.

**Refused:**
- no dated `Cube`, or no GBP;
- a rate that isn't a positive decimal in 0.5–1.5 (a sanity range against a broken file);
- a date in the future (beyond tomorrow, UTC);
- malformed XML, or an oversized body.

A refused or failed fetch is logged as a warning, and the last good rate stays.

**The daily job** (`RunDaily(ctx, checkEvery)`, the importer's pattern):
- It checks every hour, and fetches when there is no stored rate or the last fetch was over 6 hours
  ago.
- It runs beside the Scryfall import in `cmd/server`.
- **`RATES_SYNC`:** `daily` (the default) or `off`, read like `SCRYFALL_SYNC`. Tests and offline
  development use `off`.
- Several servers fetching at once is harmless: the store is an idempotent upsert.

### Storage

A new goose migration, `00007_exchange_rates.sql`, with one row per currency (only GBP for now; the
latest rate only, since price history is out of scope):

```sql
CREATE TABLE exchange_rates (
  currency   text PRIMARY KEY CHECK (currency ~ '^[A-Z]{3}$'),
  per_eur    numeric(12,6) NOT NULL CHECK (per_eur > 0),
  rate_date  date NOT NULL,
  fetched_at timestamptz NOT NULL DEFAULT now()
);
```

- **Upsert:** a fetch always updates `fetched_at`. It replaces `per_eur` and `rate_date` only when
  the new `rate_date` is the same or later, so an old file can't undo a newer rate.
- **Queries:** sqlc, as elsewhere.
- **Database role:** the app's DML role writes it. The table needs no TRUNCATE.

### API

`GET /api/rates`, public and under the general per-client limit. It returns `ExchangeRates`:

```json
{ "rates": [{ "currency": "GBP", "per_eur": 0.8712, "date": "2026-10-10" }] }
```

`rates` is empty (never null) until the first fetch succeeds.

**Contract** (Go structs in `internal/contract`, TypeScript generated by tygo):
- `ExchangeRate { Currency string; PerEUR float64 (json "per_eur"); Date string }`
- `ExchangeRates { Rates []ExchangeRate }`

The contract test checks `per_eur` serialises as a JSON number and `date` as `YYYY-MM-DD`.

## App

### The choice

- **Storage:** `lib/currency.ts`, built like `lib/theme.ts`.
  - The type is `DisplayCurrency = 'eur' | 'gbp'`; the default is EUR.
  - It's stored under `mtgcollector-currency`.
  - It's read inside a try, so blocked storage means EUR.
  - A `storage` event makes other tabs follow.
- **The switch:** `app/CurrencySwitch.tsx`, a `SegmentedControl` labelled "Currency", with
  **EUR | GBP**. It sits in the header beside the theme switch and shrinks with the header on
  phones.

### The rate

- **Fetching:** `useRates()` (TanStack Query) fetches `/api/rates`, keeps it fresh for an hour and
  needs no sign-in. The `rates` key isn't under `collection` or `groups`, so a change of user
  doesn't drop it.
- **Context:** `MoneyProvider` (in `src/app`, provided by `AppLayout`, every page's frame, so page tests get it too) combines the choice and the rate
  into a context, `{ currency: 'eur' | 'gbp', gbpPerEur: number | null, rateDate: string | null }`.
  The effective currency is GBP only when GBP is chosen and a rate is known.
- **Components:** they read this context through a hook in `src/lib`, so components still know
  nothing of the API.

### Converting and showing

- **`Price`:** every euro amount passes through `Price`; `TotalValue` uses it too. In GBP it shows
  `roundToCents(eur × rate)` formatted as GBP, with an `≈` before it.
  - The `≈` is `aria-hidden`, with a visually hidden "about ", so screen readers say "about £1.80".
  - `<data value>` carries the converted amount.
- **USD:** `Price` with `currency="usd"` is untouched.
- **Rounding:** a total converts the server's euro total. It doesn't add converted prices, so it
  can differ from the sum of its rows by a penny; the `≈` covers that.
- **Card page:** the price table's column header reads "GBP (from Cardmarket)" in GBP mode, and
  "EUR (Cardmarket)" otherwise.

### The rate note

A `RateNote` component reads the context and shows once on each page that shows values:

| Page | Where |
|---|---|
| Collection | In place of the subtitle "Values from Cardmarket, in euros" |
| Group | Under its heading |
| Search | Above the results |
| Card | In the prices section |

- **In GBP:** "Cardmarket's euro prices in pounds, at the ECB rate of 10 Oct 2026 (€1 = £0.8712)".
- **In EUR:** the collection keeps "Values from Cardmarket, in euros", and the other pages show
  nothing.
- **GBP chosen, no rate:** if no rate has been fetched yet, or `/api/rates` failed, prices stay in
  euros and the note reads "Pound prices aren't available yet, so these are in euros."

## Out of scope

- Other currencies; the table and contract allow them later.
- A rate history, and prices on past dates.
- A per-account setting (the choice is per browser, like the theme).
- Converting USD.

## Testing

Every part ships with its own tests.

**Backend unit tests:**
- parsing a saved copy of the ECB file (`testdata`): a normal day; GBP missing; a rate out of
  range; a future date; malformed XML; an oversized body;
- the "is a fetch due?" rule.

**Backend database tests:**
- the upsert: an older date doesn't replace a newer rate, and `fetched_at` always moves;
- `GET /api/rates`: an empty list before any fetch, the rate after one;
- a failed fetch keeping the last good rate;
- the contract test for the new types.

**Frontend unit tests:**
- the conversion and its rounding (half up to the penny, like the server's euros);
- the stored choice: blocked storage falls back to EUR, and other tabs follow.

**Frontend behaviour tests:**
- **Converting:** the switch changes prices and totals on the collection, a group, the search
  results and a card page. Each shows `≈£` and reads "about £". USD is left alone.
- **The note:**
  - on each page;
  - the fallback text when there's no rate (none yet, or the request failed);
  - the subtitle in EUR.
- **The choice:** remembered, and followed across tabs.

**In a real browser:** the switch on desktop and phone, in both themes, in headless Edge against
the built app (with a stored rate in the scratch database).
